# 注解

# 1 注解的作用

注解（Annotation）是 JDK 5 引入的特性，它的基本作用就是修饰编程元素。

注解相当于一种标记，在程序中加了注解就等于为程序打上了某种标记。编译器、开发工具或框架读取到这些标记后，就去干相应的事：编译期可以通过**注解处理器**（Annotation Processor，JSR 269）读取源码中的注解，运行期则可以通过**反射**读取保留到运行时的注解。

注解的语法比较简单，除了 `@` 符号的使用之外，与 Java 固有语法一致。JDK 5 内置了三种标准注解：

- `@Override`：表示当前的方法定义将覆盖父类中的方法。
- `@Deprecated`：表示当前元素不推荐使用，是被弃用的代码。Java 9 起还可以通过 `since` 和 `forRemoval` 属性说明从哪个版本废弃、是否计划移除。
- `@SuppressWarnings`：忽略编译器发出的警告信息。

后续版本又陆续增加了 `@SafeVarargs`（Java 7，抑制泛型可变参数的警告）和 `@FunctionalInterface`（Java 8，声明并检查函数式接口）等内置注解。

注解有以下几个作用：

- **编译检查**：如 `@Override` 放在方法前，如果这个方法并不是覆盖了父类方法，则编译时就能检查出来；`@FunctionalInterface` 同理。
- **编译期生成代码**：注解处理器可以在编译阶段读取注解并生成新的源码，如 Lombok 的 `@Data`、MapStruct 的 `@Mapper`。
- **运行时处理，替代配置文件**：框架在运行时通过反射读取注解完成配置，比如 Spring 从 2.5 版本开始支持基于注解的配置，如今 Spring Boot 的 `@SpringBootApplication`、JUnit 5 的 `@Test` 等都属于这一类，现在的框架基本都用注解代替了大量 XML 配置文件。
- **生成文档**：被 `@Documented` 标记的注解会出现在 Javadoc 中。注意，Javadoc 注释里常用的 `@see`、`@param`、`@return` 是文档标签，并不是注解。

# 2 元注解

Java 5 提供了四种**元注解**——负责注解其他注解；Java 8 又新增了 `@Repeatable`（见第 4 章）。

## 2.1 @Target

`@Target` 说明了注解所修饰的对象范围：注解可被用于包、类型（类、接口、枚举、注解类型）、类型成员（方法、构造方法、成员变量、枚举值）、方法参数和局部变量（如循环变量、`catch` 参数）。在注解类型的声明中使用了 `@Target` 可更加明晰其修饰的目标。

**作用**：用于描述注解的使用范围，即该注解可以用在什么地方。

取值（`ElementType` 枚举类）有：

- **CONSTRUCTOR**：用于描述构造器
- **FIELD**：用于描述成员变量（包括枚举常量）
- **LOCAL_VARIABLE**：用于描述局部变量
- **METHOD**：用于描述方法
- **PACKAGE**：用于描述包
- **PARAMETER**：用于描述参数
- **TYPE**：用于描述类、接口（包括注解类型）或 `enum` 声明
- **ANNOTATION_TYPE**：用于描述注解类型，元注解都使用这个取值
- **TYPE_PARAMETER**（Java 8）：用于描述类型参数，如 `class Box<@NonNull T>`
- **TYPE_USE**（Java 8）：用于描述任何使用类型的地方，如 `List<@NonNull String>`、`new @Interned MyObject()`
- **MODULE**（Java 9）：用于描述模块声明
- **RECORD_COMPONENT**（Java 16）：用于描述 `record` 的组件

## 2.2 @Retention

`@Retention` 定义了该注解被保留的时间长短：某些注解仅出现在源代码中，而被编译器丢弃；而另一些却被编译在 class 文件中；编译在 class 文件中的注解可能会被虚拟机忽略，而另一些在 class 被装载时将被读取（请注意并不影响 class 的执行，因为注解与 class 在使用上是被分离的）。使用 `@Retention` 可以限制注解的“生命周期”。

**作用**：用于描述注解的生命周期，即注解在什么范围内有效。

取值（`RetentionPolicy` 枚举类）有：

- SOURCE：在源文件中有效，如 `@Override`、Lombok 的注解
- CLASS：在 class 文件中有效，但运行时无法通过反射读取，这是未指定 `@Retention` 时的默认值
- RUNTIME：在运行时有效，可以通过反射读取，框架使用的注解大多是这一类

## 2.3 @Documented

`@Documented` 是一种标记性注解，被其标记的注解会被包含在 Javadoc 文档中。

## 2.4 @Inherited

`@Inherited` 也是一种标记性注解，被其标记的注解会允许子类继承。如果一个使用了 `@Inherited` 修饰的注解类型被用于一个类，则该注解将被用于该类的子类。

需要注意的是，`@Inherited` 只对用在类上的注解有效：被 `@Inherited` 标记的注解只会被类的子类所继承，类并不从它所实现的接口继承注解，方法也不从它所重写的方法继承注解。

如果我们使用 `java.lang.reflect` 去查询一个 `@Inherited` 类型的注解时，反射代码将检查该类和其父类，直到发现指定的注解类型，或者到达类继承结构的顶层。

# 3 自定义注解

自定义注解的格式为：

`public @interface 注解名 {定义体}`

例如：

```java
@Target(value = { ElementType.FIELD })
@Retention(value = RetentionPolicy.RUNTIME)
@Documented
public @interface NotNull {

	int code() default -1;

	String message() default "";
}
```

`@interface` 用来声明一个注解，自动继承了 `java.lang.annotation.Annotation` 接口，在自定义注解时，不能继承其他的注解或接口。

定义体中的每一个方法实际上是声明了一个配置参数（称为注解元素），这些方法隐式为 `public`，不能使用其他访问修饰符，也不能有参数；方法的名称就是参数的名称，返回值类型就是参数的类型。可以通过 `default` 来声明参数的默认值。

注解参数支持的数据类型：

- 所有基本数据类型（`byte`、`int`、`short`、`long`、`double`、`float`、`boolean`、`char`）
- `String` 类型
- `Class` 类型
- `Enum` 类型
- `Annotation` 类型
- 以上所有类型的数组

注解元素必须有确定的值，要么在定义注解的默认值中指定，要么在使用注解时指定，**非基本类型的注解元素的值不可为 `null`**。因此，使用空字符串或 0 作为默认值是一种常用的做法。这个约束使得处理器很难判断一个元素是否缺失，因为每个注解的声明中，所有元素都存在，并且都具有相应的值，为了绕开这个约束，我们只能定义一些特殊的值，例如空字符串或者负数，以此表示某个元素不存在，在定义注解时，这已经成为一个习惯用法。

如果成员名称是 `value`，在赋值过程中可以简写；如果成员类型为数组，但是只赋值一个元素，则也可以简写。上面的例子可以简写为：

```java
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface NotNull {

	int code() default -1;

	String message() default "";
}
```

上例自定义了名为 `@NotNull` 的注解，作用对象为字段（`FIELD`），其目的是对成员变量进行非空检验。可是，到底怎么利用它来进行检验呢？

使用注解最主要的部分在于对注解的处理，那么就会涉及到注解处理器。从原理上讲，运行时的注解处理器就是通过反射机制获取被检查字段上的注解信息，然后根据注解元素的值进行特定的处理。

比如，在某网站注册用户，用户输入的信息会被封装成一个 `User` 对象：

```java
public class User {

	@NotNull(message = "用户昵称不能为空")
	private String userName;

	@NotNull(message = "密码不能为空")
	private String password;

	private Integer age;

	public String getUserName() {
		return userName;
	}

	public void setUserName(String userName) {
		this.userName = userName;
	}

	public String getPassword() {
		return password;
	}

	public void setPassword(String password) {
		this.password = password;
	}

	public Integer getAge() {
		return age;
	}

	public void setAge(Integer age) {
		this.age = age;
	}
}
```

要求用户昵称与密码不能为空，因此 `userName` 与 `password` 字段被 `@NotNull` 注解。

后台程序接收到 `User` 对象后，可以通过反射机制探知哪些字段被 `@NotNull` 注解了，如果全部满足要求再进行下一步业务逻辑；反之，返回错误页面。

```java
public class UserTest {

	public static boolean testNotNull(User user) throws IllegalArgumentException, IllegalAccessException {
		Class<?> clazz = user.getClass(); // 获取 User 的 Class 对象
		Field[] userFields = clazz.getDeclaredFields(); // 获取 User 的所有 Field 对象
		for (Field field : userFields) {
			field.setAccessible(true); // User 中的 Field 都是 private 的，所以要先 setAccessible
			NotNull notNullAnnotation = field.getAnnotation(NotNull.class); // 获取 Field 的 NotNull 注解对象
			if (notNullAnnotation != null) { // 如果该 Field 被 NotNull 注解了，那么字段不能为空
				if (field.get(user) == null) {
					System.out.println(notNullAnnotation.message());
					return false;
				}
			}
		}

		return true;
	}

	public static void main(String[] args) throws IllegalArgumentException, IllegalAccessException {
		User user = new User();
		user.setUserName("chenlongfei");
		testNotNull(user);
	}
}
```

由于只填写了昵称而没填密码，不能通过验证，控制台打印出：

```text
密码不能为空
```

而该信息正是在 `@NotNull` 注解 `password` 字段时由 `message` 定义的。

# 4 新版本与实践

## 4.1 可重复注解

Java 8 之前，同一个位置不能重复使用同一个注解。Java 8 引入了元注解 `@Repeatable`，只需再定义一个“容器注解”，就可以在同一处多次使用：

```java
@Repeatable(Schedules.class)
@Retention(RetentionPolicy.RUNTIME)
public @interface Schedule {
	String cron();
}

@Retention(RetentionPolicy.RUNTIME)
public @interface Schedules {
	Schedule[] value();
}

@Schedule(cron = "0 0 1 * * ?")
@Schedule(cron = "0 0 13 * * ?")
public void doTask() { }
```

通过反射读取时，使用 `getAnnotationsByType(Schedule.class)` 即可拿到全部的 `@Schedule`。

## 4.2 类型注解

Java 8 新增的 `ElementType.TYPE_USE` 让注解可以出现在任何使用类型的地方，例如 `List<@NonNull String>`。配合 Checker Framework、NullAway 等工具，可以在编译期发现潜在的空指针问题。

## 4.3 使用标准的校验注解

本文的 `@NotNull` 示例演示了注解处理的原理。实际项目中，一般不需要自己实现这类校验，而是使用 Jakarta Bean Validation 规范（原 Java EE 的 `javax.validation`，现包名为 `jakarta.validation`）提供的 `@NotNull`、`@NotBlank`、`@Size` 等注解，由 Hibernate Validator 等实现完成校验；在 Spring Boot 中，只需在 Controller 参数上加 `@Valid` 即可自动触发。

总结一下：注解本身只是一种元数据，真正起作用的是读取它的程序。理解 `@Target` 和 `@Retention` 这两个元注解，就能判断一个注解能用在哪里、在编译期还是运行期被处理。
