# 正则表达式

# 1 表达式基础

## 1.1 句点符号

假设在玩英文拼字游戏，想要找出三个字母的单词，而且这些单词必须以“t”字母开头，以“n”字母结束。要构造出这个正则表达式，可以使用一个通配符——句点符号“.”。这样，完整的表达式就是“t.n”，它匹配“tan”、“ten”、“tin”和“ton”，还匹配“t#n”、“tpn”甚至“t n”，还有其他许多无意义的组合。这是因为句点符号匹配几乎所有字符，包括空格、Tab 字符。

需要注意的是，默认情况下句点符号**不匹配换行符**（`\n`、`\r` 等行结束符）。如果希望它也匹配换行符，需要开启 `Pattern.DOTALL` 标志，或在表达式开头加上内嵌标志 `(?s)`。

## 1.2 方括号符号

为了解决句点符号匹配范围过于广泛这一问题，你可以在方括号（“[]”）里面指定看来有意义的字符。此时，只有方括号里面指定的字符才参与匹配。也就是说，正则表达式“t[aeio]n”只匹配“tan”、“ten”、“tin”和“ton”。但“toon”不匹配，因为在方括号之内只能匹配单个字符。

正则表达式默认区分大小写，“t[aeio]n”不匹配“Ten”。如果需要忽略大小写，可以使用 `Pattern.CASE_INSENSITIVE` 标志或内嵌标志 `(?i)`。

此外，方括号内还可以用“-”表示跨度，如“[a-g]”匹配字母表中 a 到 g 的小写字母，“[1-9]”匹配 1 到 9 的数字。

可以使用”&&”取交集，比如”[1-9&&[^456]]”，匹配 1 到 9 中除了 4、5、6 以外的数字。这种语法在 Java 中最为常见；JavaScript 在 ES2024 引入 `v` 标志后也支持字符类集合运算，而 Python 的标准 `re` 模块不支持。

## 1.3 “或”符号

如果除了上面匹配的所有单词之外，还想要匹配“toon”，那么，你可以使用“|”操作符。“|”操作符的基本意义就是“或”运算。要匹配“toon”，使用“t(a|e|i|o|oo)n”正则表达式。这里不能使用方括号，因为方括号只允许匹配单个字符；这里必须使用圆括号“()”。圆括号还可以用来分组。

## 1.4 表示匹配次数的符号

| ----- | ----------------------- |

| *     | 0 次或多次，即任意多次  |
| {n}   | 恰好 n 次               |

“^”用在方括号内的第一个位置时称为“否”符号，表示不想要匹配的字符；用在方括号外时，它是表示开头的边界匹配符（见 1.8 节）。例如，下图的正则表达式匹配第一个字符不是“X”、后面跟着若干小写字母的字符串。

严格来说，`[^X]` 匹配的是除“X”以外的**任意**字符，包括空格、数字和标点。如果要求“以字母开头、但不以 X 开头的单词”，可以写成 `\b[A-WYZa-z][a-z]*\b`。

## 1.6 圆括号

### 1.6.1 限定量词作用的范围

```text
(cat)?		匹配 0 个或 1 个“cat”
(cat)+		匹配 1 个或多个“cat”
```

### 1.6.2 限定多选结构的范围

```text
(cat|dog)	匹配“cat”或“dog”
```

### 1.6.3 分组捕获

位于圆括号之间的模式匹配的内容都会被捕获，当模式中有嵌套的圆括号时，分组的编号会按照左括号出现的位置依次进行。编号为 0 的分组代表整个表达式匹配到的内容。

例如，`([A-Za-z](\d{2}))((-)\d{2})` 匹配“A22-33”时，匹配情况如下：

```text
第一个出现的圆括号中的正则表达式为：[A-Za-z](\d{2})
匹配结果 Group 1:   A22

第二个出现的圆括号中的正则表达式为：\d{2}
匹配结果 Group 2:   22

第三个出现的圆括号中的正则表达式为：(-)\d{2}
匹配结果 Group 3:   -33

第四个出现的圆括号中的正则表达式为：-
匹配结果 Group 4:   -
```

### 1.6.4 分组不捕获

当圆括号与“?:”组合使用时，表示非捕获型分组。圆括号的内容不作为捕获对象，也不占用分组编号。当圆括号中的内容不是想捕获的对象时，采用非捕获圆括号可以提高匹配效率。

例如，`(\w(?:\d{2}))((?:-)\d{2})` 匹配“A22-33”的情况如下：

```text
Group 1:   A22
Group 2:   -33
```

注：`\d{2}` 匹配的“22”没有被捕获，`-` 匹配的“-”也没有被捕获。

### 1.6.5 反向引用捕获文本

以 `([ab])\1` 为例，圆括号内的“[ab]”可以匹配“a”或“b”，后面的“\1”是反向引用，代表第 1 个分组实际匹配到的文本。如果捕获组匹配到“a”，那么反向引用也就只能匹配“a”；同理，如果捕获组匹配到的是“b”，那么反向引用也就只能匹配“b”。由于后面反向引用“\1”的限制，要求必须是两个相同的字符，在这里也就是“aa”或者“bb”才能匹配成功。

### 1.6.6 前瞻

当圆括号与“?=”组合使用时，表示前瞻（正向先行断言），代表该表达式会作为匹配校验，但不会出现在匹配结果字符串里面。

例如，`John(?= Resig)` 的匹配情况如下：

```text
John：不匹配，因为后面没有跟着“ Resig”
John Backus：不匹配，后面跟着的不是“ Resig”
John Resig：匹配，John 后面跟着“ Resig”。但是匹配的结果是“John”而不是“John Resig”
```

注意空格要写在断言内部。如果写成 `John (?=Resig)`，空格在断言外部，匹配结果就会是“John ”（带一个空格）。

## 1.7 预定义字符

| 符号 | 意义                      |
| ---- | ------------------------- |
| \d   | 数字字符：[0-9]           |
| \D   | 非数字字符                |
| \s   | 空白字符：[ \t\n\x0B\f\r] |
| \S   | 非空白字符                |
| \w   | 单词字符：[a-zA-Z_0-9]    |
| \W   | 非单词字符                |
| \h   | 水平空白字符（Java 8+）   |
| \R   | 任意换行序列（Java 8+）   |

使用时有两点需要注意：

- 在 Java 字符串字面量中，反斜杠本身需要转义，因此 `\d` 要写成 `"\\d"`，匹配一个真正的反斜杠则要写成 `"\\\\"`。Java 15 引入的文本块（Text Block）同样需要转义反斜杠。
- `\d`、`\w` 默认只匹配 ASCII 字符，不包括中文、全角数字等。如果需要按 Unicode 语义匹配，可以开启 `Pattern.UNICODE_CHARACTER_CLASS` 标志（内嵌标志 `(?U)`）；匹配汉字可以使用 `\p{IsHan}`。

## 1.8 边界匹配字符

| 符号 | 意义                                                         |
| ---- | ------------------------------------------------------------ |
| ^    | 输入的开头；开启 `MULTILINE` 模式后表示行首                  |
| $    | 输入的结尾（允许末尾有一个行结束符）；开启 `MULTILINE` 模式后表示行尾 |
| \b   | 单词边界                                                     |
| \B   | 非单词边界                                                   |
| \A   | 输入的开头                                                   |
| \G   | 上一个匹配的结尾                                             |
| \Z   | 输入的结尾，但不包括末尾的行结束符（如果有的话）             |
| \z   | 输入的结尾                                                   |

`MULTILINE` 模式可以通过 `Pattern.MULTILINE` 标志或内嵌标志 `(?m)` 开启。

## 1.9 匹配模式

正则表达式的量词有三种匹配模式：

- 贪婪（greedy）
- 勉强（reluctant，也叫懒惰）
- 侵占（possessive，也叫占有）

| 贪婪   | 勉强    | 侵占    | 意义                            |
| ------ | ------- | ------- | ------------------------------- |
| X?     | X??     | X?+     | 匹配 X 零次或一次               |
| X*     | X*?     | X*+     | 匹配 X 零次或多次               |
| X+     | X+?     | X++     | 匹配 X 一次或多次               |
| X{n}   | X{n}?   | X{n}+   | 匹配 X n 次                     |
| X{n,}  | X{n,}?  | X{n,}+  | 匹配 X 至少 n 次                |
| X{n,m} | X{n,m}? | X{n,m}+ | 匹配 X 至少 n 次，但不多于 m 次 |

假定要分析的字符串是：`xfooxxxxxxfoo`。

- `.*foo`（贪婪模式）：

  模式分为子模式 p1（`.*`）和子模式 p2（`foo`）两个部分。其中 p1 中的量词使用默认的贪婪模式。匹配开始时，吃入所有字符 `xfooxxxxxxfoo` 去匹配子模式 p1。匹配成功，但这样一来就没有剩余字符去匹配子模式 p2，本轮匹配失败；第二轮，减少 p1 部分的匹配量，吐出最后一个字符，把字符串分割成 `xfooxxxxxxfo` 和 `o` 两个子字符串 s1 和 s2，s1 匹配 p1，但 s2 不匹配 p2，本轮匹配失败；第三轮，再次减少 p1 部分匹配量，吐出两个字符，字符串被分割成 `xfooxxxxxxf` 和 `oo` 两部分，结果同上；第四轮，再次减少 p1 匹配量，字符串分割成 `xfooxxxxxx` 和 `foo` 两个部分，这次 s1、s2 分别和 p1、p2 匹配。停止尝试，返回匹配成功，匹配结果是整个字符串 `xfooxxxxxxfoo`。

- `.*?foo`（勉强模式）：

  最小匹配方式。第一次尝试匹配，p1 由于是 0 或任意次，因此先匹配 0 个字符，用字符串去匹配 p2，失败；第二次，读入第一个字符 x，尝试和 p1 匹配，匹配成功，字符串剩余部分 `fooxxxxxxfoo` 中前三个字符和 p2 也是匹配的。因此，停止尝试，返回匹配成功，匹配结果是 `xfoo`。在这种模式下，如果继续调用 `find()` 在剩余字符串中寻找，还会找到第二个匹配 `xxxxxxfoo`；而在贪婪模式下，由于第一次匹配成功的子串就已经是所有字符，因此不存在第二个匹配子串。

- `.*+foo`（侵占模式）：

  匹配开始时读入所有字符，和 p1 匹配成功，但没有剩余字符去和 p2 匹配。侵占模式不会回溯吐出字符，因此匹配失败。

简单地说，贪婪模式和侵占模式相比，贪婪模式会在只有部分匹配成功的条件下，依次从多到少减少已匹配部分的数量（即回溯），将字符留给模式其他部分去匹配；而侵占模式则是占有所有能匹配成功的部分，绝不留给其他部分使用。

侵占模式并非 Java 独有，PCRE、PHP、Ruby 等引擎以及 Python 的第三方 `regex` 模块都支持，JavaScript 目前不支持。由于不回溯，它常被用来优化性能、避免灾难性回溯（见 3.6 节），但日常业务中较少使用。

# 2 Java 实例

JDK 中与正则表达式相关的类位于 `java.util.regex` 包下，核心是 `Pattern` 和 `Matcher` 两个类：`Pattern` 是编译后的正则表达式，不可变且线程安全；`Matcher` 是在某个输入上执行匹配的引擎，有状态、非线程安全。

```java
String regex = "((A+)(B(C)))";
String input = "ABC-AABC-AAAAABCD";

Pattern pattern = Pattern.compile(regex);
Matcher matcher = pattern.matcher(input);

int groupCount = matcher.groupCount();
// regex 被圆括号分为四组，按照左括号的出现位置，分别为：((A+)(B(C)))、(A+)、(B(C))、(C)
// group(0) 表示整个表达式匹配到的内容
// 匹配的时候，还是按照 A+BC 去搜索，只不过每次匹配成功后，会将搜到的字符串按照上面的四组规则分为四个子串存储起来
while (matcher.find()) {
    System.out.print("匹配结果：");
    for (int i = 0; i <= groupCount; i++) {
        System.out.print("group" + i + ":" + matcher.group(i) + "\t");
    }
    System.out.println();
}
```

输出：

```text
匹配结果：group0:ABC	group1:ABC	group2:A	group3:BC	group4:C
匹配结果：group0:AABC	group1:AABC	group2:AA	group3:BC	group4:C
匹配结果：group0:AAAAABC	group1:AAAAABC	group2:AAAAA	group3:BC	group4:C
```

`groupCount()` 返回的是捕获组的数量（不含第 0 组），因此循环条件要写成 `i <= groupCount`，否则会漏掉最后一组。

另外要区分 `Matcher` 的三种匹配方法：

- `matches()`：整个输入必须完全匹配表达式。
- `lookingAt()`：从输入开头开始匹配，不要求匹配到结尾。
- `find()`：在输入中查找下一个匹配的子串，可以反复调用。

# 3 进阶与新版本特性

## 3.1 环视

1.6.6 节的前瞻属于“环视”（lookaround）的一种。环视只做位置校验，不消耗字符，Java 支持全部四种：

| 语法       | 名称     | 含义                       |
| ---------- | -------- | -------------------------- |
| `(?=X)`    | 正向先行 | 当前位置后面能匹配 X       |
| `(?!X)`    | 负向先行 | 当前位置后面不能匹配 X     |
| `(?<=X)`   | 正向后行 | 当前位置前面能匹配 X       |
| `(?<!X)`   | 负向后行 | 当前位置前面不能匹配 X     |

例如，`(?<=¥)\d+` 匹配“¥”后面的数字但不包含“¥”；`^(?=.*\d)(?=.*[a-z]).{8,}$` 是常见的密码强度校验，要求至少 8 位且同时包含数字和小写字母。

Java 的后行断言要求 X 的长度有上限，不能使用 `*`、`+` 这类无上限的量词。

## 3.2 命名分组

Java 7 开始支持命名分组 `(?<name>X)`，可以用名称代替数字编号来获取分组内容，表达式改动时不容易出错：

```java
Pattern p = Pattern.compile("(?<year>\\d{4})-(?<month>\\d{2})-(?<day>\\d{2})");
Matcher m = p.matcher("2026-10-16");
if (m.matches()) {
    System.out.println(m.group("year")); // 2026
}
// 替换字符串中用 ${name} 引用命名分组
String s = p.matcher("2026-10-16").replaceAll("${day}/${month}/${year}"); // 16/10/2026
```

表达式内部可以用 `\k<name>` 反向引用命名分组。Java 20 又为 `Matcher` 和 `MatchResult` 增加了 `namedGroups()` 方法，可以获取分组名到编号的映射。

## 3.3 匹配标志

除了在 `Pattern.compile(regex, flags)` 中传入标志，还可以在表达式中使用内嵌标志，常用的有：

| 标志常量                   | 内嵌写法 | 作用                          |
| -------------------------- | -------- | ----------------------------- |
| `CASE_INSENSITIVE`         | `(?i)`   | 忽略大小写                    |
| `MULTILINE`                | `(?m)`   | `^`、`$` 按行匹配             |
| `DOTALL`                   | `(?s)`   | `.` 匹配换行符                |
| `COMMENTS`                 | `(?x)`   | 忽略空白，允许 `#` 注释       |
| `UNICODE_CHARACTER_CLASS`  | `(?U)`   | `\w`、`\d` 等按 Unicode 匹配  |

## 3.4 预编译并复用 Pattern

`String.matches()`、`String.replaceAll()`、`String.split()` 等便捷方法每次调用都会重新编译正则表达式（`split` 对单个普通字符有快速路径）。在循环或高频调用的场景下，应该把 `Pattern` 定义为常量复用：

```java
private static final Pattern PHONE = Pattern.compile("1[3-9]\\d{9}");

public static boolean isPhone(String s) {
    return PHONE.matcher(s).matches();
}
```

`Pattern` 是线程安全的，可以放在静态常量中共享；`Matcher` 不是线程安全的，每次使用时新建即可。

## 3.5 与 Stream 和函数式接口结合

Java 8 之后，正则相关 API 陆续增加了对 Stream 和函数式接口的支持：

| 版本    | API                                   | 作用                                                    |
| ------- | ------------------------------------- | ------------------------------------------------------- |
| Java 8  | `Pattern.asPredicate()`               | 转为 `Predicate<String>`，语义是 `find()`（包含即可）   |
| Java 8  | `Pattern.splitAsStream()`             | 按正则切分，返回 `Stream<String>`                       |
| Java 9  | `Matcher.results()`                   | 返回所有匹配结果的 `Stream<MatchResult>`                |
| Java 9  | `Matcher.replaceAll(Function)`        | 根据每个匹配结果动态计算替换内容                        |
| Java 11 | `Pattern.asMatchPredicate()`          | 转为 `Predicate<String>`，语义是 `matches()`（完全匹配）|

```java
Pattern number = Pattern.compile("\\d+");

// 提取所有数字：[12, 345, 6]
List<String> nums = number.matcher("a12b345c6").results()
        .map(MatchResult::group)
        .toList();

// 把每个数字乘以 2：a24b690c12
String doubled = number.matcher("a12b345c6")
        .replaceAll(r -> String.valueOf(Integer.parseInt(r.group()) * 2));

// 过滤出完全由数字组成的字符串：[123]
List<String> pure = Stream.of("123", "a1", "45b")
        .filter(number.asMatchPredicate())
        .toList();
```

（`Stream.toList()` 为 Java 16 新增，更早的版本可使用 `collect(Collectors.toList())`。）

## 3.6 警惕灾难性回溯（ReDoS）

Java 的正则引擎基于回溯实现。当表达式中存在嵌套量词或可以重叠匹配的分支时，例如 `(a+)+$`、`(a|aa)*$`，面对一个“几乎匹配”的输入（如很长的一串 `a` 后面跟一个 `b`），回溯次数会随输入长度呈指数级增长，导致 CPU 被长时间占满。攻击者可以借此构造恶意输入，这类攻击被称为 ReDoS（正则表达式拒绝服务）。

常见的防范措施有：

- 避免嵌套量词和相互重叠的分支，尽量写出无歧义的表达式。
- 在不需要回溯的地方使用侵占量词（如 `a++`）或原子分组 `(?>X)`。
- 对用户输入的长度做限制，不要直接用用户提供的字符串作为正则表达式；如果必须使用，先用 `Pattern.quote()` 转义。
- 对不可信输入的匹配有严格性能要求时，可以考虑使用基于有限自动机、保证线性时间的引擎，如 Google 的 RE2/J。

# 4 总结

- 正则表达式由字符类（`[]`、`.`、`\d` 等）、量词（`?`、`*`、`+`、`{n,m}`）、分组（`()`、`(?:)`、`(?<name>)`）、边界（`^`、`$`、`\b`）和环视等元素组合而成。
- 注意几个常见误区：`.` 默认不匹配换行符，`^`、`$` 默认匹配整个输入的首尾，连字符只在方括号内表示范围，Java 字符串中反斜杠需要写两次。
- 量词有贪婪、勉强、侵占三种模式，区别在于是否回溯以及回溯的方向。
- Java 中通过 `Pattern` 和 `Matcher` 使用正则，`Pattern` 应预编译复用；Java 7 的命名分组，Java 8/9/11 的 `asPredicate`、`results()`、`replaceAll(Function)`、`asMatchPredicate` 等 API 让正则可以方便地与 Stream 结合。
- 处理不可信输入时要警惕灾难性回溯带来的 ReDoS 风险。
