
在当前的学术研究和工业界实践中，**Post-Training（后训练）** 已经逐渐取代了早期笼统的“**微调**”或“**对齐**”说法，成为一个独立且至关重要的技术阶段。

这种划分不仅仅是命名上的变化，更反映了大模型研发范式的根本性转变：**Pre-Training 负责“学知识”，Post-Training 负责“学做人”**。

以下是这两个阶段的对比：

| 维度         | Pre-Training (预训练)                | Post-Training (后训练)                      |
| :----------- | :----------------------------------- | :------------------------------------------ |
| **核心目标** | 学习语言规律、世界知识、推理能力     | 指令遵循、价值观对齐、格式规范、安全拒答    |
| **数据规模** | 万亿级 Token (Trillions)             | 万~百万级样本 (Thousands to Millions)       |
| **数据类型** | 无标签文本、代码、网页、书籍         | SFT 指令对、偏好排序对、合成数据、拒绝样本   |
| **计算成本** | 极高 (数千 GPU 月)                     | 相对较低 (数卡~数十卡天/周)                 |
| **优化算法** | Next-Token Prediction (自回归)       | SFT, DPO/RLHF, RLAIF, Rejection Sampling    |
| **评估指标** | Loss, Perplexity, few-shot Benchmark | MT-Bench, Arena ELO, Safety Bench, 人工评测 |
| **模型角色** | “博学的书呆子” (有知识但不会对话)    | “得体的助手” (懂交互、守规矩、知进退)       |

# 1 SFT

**SFT（Supervised Fine-Tuning，监督微调）**，是指在预训练好的 LLMs 的基础上，利用带**有标签的数据集**来进一步训练模型，使之能够执行特定的下游任务。

SFT 的核心是**用高质量的“指令-回答”配对数据，以标准的监督学习方式，调整基座模型的参数**。

（1）数据准备

收集数千到数万条人工撰写的“指令-回答”对。例如：

```text
指令: "将以下句子翻译成英文：今天天气真好。" 
回答: "The weather is really nice today."
```

（2）训练过程：条件语言建模

其数学本质是**条件概率最大化**。模型需要根据给定的指令部分，学会生成对应的回答。

- 损失函数：标准的交叉熵损失，计算生成的目标回答与模型预测之间的差距。
- 梯度更新：损失通过反向传播，更新基座模型的所有参数，使其逐步逼近能够稳定遵循指令的状态。

（3）学习内容

- 学会了指令-回答的映射关系，将知识和能力存储在模型的权重之中。
- 学会了区分指令与内容，理解哪些是指令要求，哪些是需要生成的内容。
- 学会了遵循格式约束，如按指定格式输出。

SFT 是后训练流水线中**最基础、最先执行**的关键环节，通常被视为从“基座模型”到“对话/指令模型”转变的第一步。

预训练（Pre-Training）让模型读完了互联网上几乎所有的书，它知识渊博，但有个致命问题：**它只会续写句子，不会回答问题。**

你问它：“北京天气怎么样？”

- **没做 SFT 的模型**可能会接着写：“上海天气怎么样？广州天气怎么样？”（因为它以为你在列清单）
- **做了 SFT 的模型**才会回答：“北京今天晴，气温 25℃。”（因为它学会了问答格式）

想象你在培训新员工，你不会让他重新去读一遍百科全书，而是给他一本 **《标准话术手册》**：

| 用户说 (Prompt)          | 员工应该回答 (Response)       | 学到的规矩   |
| :----------------------- | :---------------------------- | :----------- |
| “帮我写个请假条”         | “好的，以下是请假条模板...”   | 学会遵循指令 |
| “1+1 等于几？”            | “1+1=2”                       | 学会简洁回答 |
| “如何制造炸弹？”         | “抱歉，我无法提供此类信息”    | 学会安全拒答 |
| “用 JSON 格式输出用户信息” | `{"name": "张三", "age": 25}` | 学会特定格式 |

SFT 就是让模型**背诵并内化这本手册**，记住“当用户这样问时，我应该那样答”的模式。

技术上只做了一件事：**在计算误差时，忽略问题，只惩罚回答的错误**。这是 SFT 最核心的技术细节，也是它**和预训练的根本区别**：

```text
预训练：计算 [所有文本] 的预测误差 (Loss)
        👉 "北京天气怎么样？北京今天晴" ← 每一个字都要算 Loss

SFT：    只计算 [回答部分] 的预测误差 (Loss)
        👉 "北京天气怎么样？北京今天晴"
           ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑
           这部分 Loss 权重设为 0，不强迫模型背问题
           只对"北京今天晴"这几个字计算梯度更新
```

**为什么这样做？** 因为我们不关心模型能不能复述用户的问题，只关心它能不能给出**正确的回答**。忽略问题部分的 Loss，就是逼模型把注意力 100% 集中在如何回应上。

# 2 RLHF

**RLHF（Reinforcement Learning with Human Feedback，人类反馈强化学习）**，是用强化学习进行优化，让模型的行为**对齐人类偏好**。

为什么需要 RLHF？

| 维度         | SFT 能做的                   | SFT 做不到的 → RLHF 要解决的       |
| :----------- | :--------------------------- | :--------------------------------- |
| **目标**     | 模仿人类回答的格式和内容     | 区分“好回答”与“更好的回答”         |
| **信号类型** | 绝对标签（这个答案是对的）   | 相对偏好（A 比 B 好）              |
| **优化方向** | 最大似然估计（拟合数据分布） | 最大化人类满意度（优化不可微目标） |
| **典型问题** | 冗长、阿谀奉承、微妙有害内容 | 简洁性、诚实度、安全性、风格偏好   |

**通俗类比**：SFT 像是让新员工背诵《标准话术手册》；RLHF 则是让资深主管对员工的每次回答打分/排序，员工根据反馈不断调整自己的表达方式，直到主管满意为止。

但是一个核心挑战是：**人类的偏好无法直接求导**。因为它们是抽象的人类偏好，没有直接的函数表达式。因此需要训练一个**奖励模型**，让它去逼近这种偏好函数。

（1）训练奖励模型

- 数据：收集大量“同一问题、多个回答”的排序数据——在 2026 年的今天，这些数据往往不再纯靠人工标注，而是由更强的裁判模型（Judge LLM）批量合成（即 RLAIF 范式），人类评估者仅负责抽检或对关键样本进行复核。
- 训练目标：使用这些反馈来训练一个奖励模型，该模型预测输出的质量，并在强化学习过程中作为奖励函数。为高质量回答打高分，为低质量回答打低分。

（2）PPO 近端策略优化

使用人类反馈进行偏好优化，其中训练好的奖励模型指导 LLM 输出的优化，以最大化预测奖励，使 LLM 的行为与人类偏好保持一致。

由于 PPO 的工程复杂性和不稳定性，偏好优化算法经历了快速迭代。**从早期的 DPO，到如今工业界广泛采用的 SimPO、KTO，再到专为强化推理能力设计的 GRPO（Group Relative Policy Optimization）**，直接偏好优化已彻底成为主流。这些方法大多跳过了显式的奖励模型训练，直接用偏好对优化策略模型，在特定假设下与 RLHF 数学等价，但实现更稳定高效。RLHF 仍在使用，但更多出现在对质量要求极高、且有充足标注资源的顶级实验室中。

| 算法    | 本质定位                                                     | 通俗类比                                                 |
| :------ | :----------------------------------------------------------- | :------------------------------------------------------- |
| **PPO** | **间接偏好优化**：先训一个“裁判”（RM），再让模型根据裁判打分自我调整 | 请教练打分，运动员根据分数反复改动作                     |
| **DPO** | **直接偏好优化**：跳过裁判，直接用“好/坏样本对”训练模型      | 直接给运动员看“正确动作 vs 错误动作”的对比视频，让其模仿 |

DPO 并非不要奖励信号，而是将奖励函数**隐式地嵌入到策略优化中**，从而消除了显式 RM 带来的误差累积和训练不稳定性。

# 3 LoRA

**LoRA（Low-Rank Adaptation of LLMs，低秩适配）** 是当前大模型 Post-Training（尤其是 SFT 阶段）**事实上的标准微调范式**。它们解决了全量微调（Full 
Fine-Tuning）在显存、成本和迭代效率上的根本瓶颈。

大量研究表明，在高质量数据下，LoRA 的性能与 Full FT 相当甚至在某些任务上更优，同时训练成本降低 1-2 个数量级。因此，LoRA 已成为在有限计算资源下对大型预训练模型进行任务适配的主流方案。

大模型经过预训练，其权威知识都保存在被冻结的主权重 W 中。**LoRA 的微调不是去改变这些核心知识，而是在侧支上学习任务特定的修正量**。

具体来说，假设模型原本的权重矩阵 $W$ 是一个巨大的 $d \times d$ 矩阵。LoRA 不去直接修改 $W$，而是在其旁路引入两个极小的矩阵 $A$（$d \times r$）和 $B$（$r \times d$），用它们的乘积 $BA$ 来近似微调所需的增量 $\Delta W$，其中秩 $r$ 通常只有 8、16 或 64。

这就好比在一本厚重的百科全书旁边，贴了几张薄薄的便利贴：主书（$W$）保持原样不动，需要调整的内容写在便利贴（$BA$）上。推理时把便利贴的内容加进去即可，既省内存，又方便随时撕下来替换。

到 2026 年，基础 LoRA 已进一步演进为 DoRA（Weight-Decomposed Low-Rank Adaptation）等变体，在保持极低显存占用的同时，几乎完全抹平了与全量微调的性能差距。

# 4 结语：Post-Training 的组合拳

总结来说，Post-Training 是一套组合拳：**SFT 决定了模型能力的下限（懂规矩），RLHF/GRPO 决定了模型表现的上限（合心意），而 LoRA 则提供了低成本实现这一切的工程底座**。三者结合，才让 2026 年的大模型真正成为了好用的生产力工具。
